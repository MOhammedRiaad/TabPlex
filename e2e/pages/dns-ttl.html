How TTL values control DNS caching

Every DNS record carries a time to live, usually shortened to TTL, measured in seconds. A resolver may keep the record for that long, and it must ask the authoritative server again once the time has passed.

Choosing a TTL

A record with a TTL of 3600 seconds can be reused for one hour before the resolver contacts the authoritative server again. Short values such as 300 seconds let an owner change a website address quickly, but they cause more lookups overall.

Trade-offs

Long TTL values reduce traffic and make pages load faster for visitors. Short TTL values make changes visible sooner, which matters during a server move or an outage. Most site owners pick a middle value and lower it a day before a planned change.
